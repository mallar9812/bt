What to discount, and why

The pre-test window overlaps version 2 Caution
  • PAB uses the same two variants over Aug 17 – Sep 15, 2026. Version 2 ran those variants from Aug 14 to about Sep 7, so the pre-test gap can already contain an effect of the feature
  • Adjusted results are observed minus that gap: where the gap is large (Clear/DAU +2.0%, W2E revenue −2.8%, IAP +14%) the adjusted number can differ a lot from the observed one. The summary and results tables show both
  • The pre-test table also has a bucket of smaller cohorts (36% of pre-test DAU) that no single cohort cell can use; cohort cells use their own pre-test cohort
The PAB is measured on existing users only Caution

Method and limits

Test design

  • Two-variant test with no control: var2 is compared with var1 (the reference variant); nothing is pooled across versions, variants or platforms
  • Paired two-sided t-test over days, 95% interval used for the reading, Conf shown
  • Window Sep 17 – Oct 12, 2026: launch day (Sep 16) excluded, and the window ends Oct 12 to match the earlier read of this version. The test is still live
  • Rolling retention drops the last 3 days (D1) and 5 days (D3) so the flags are mature; rolling LTV D7 drops the last 7 days
  • Classic retention, LTV and LTDays are paired over install dates (Sep 17 onwards) instead of activity dates, for the horizons that have matured: 26 install days for D1, 13 for D14, 12 for D15; D30 is not computable yet

PAB adjustment

  • PAB (pre-A/B baseline) is the same two variants' difference over the 30 days before the window (Aug 17 – Sep 15, 2026, which overlaps version 2), for the same cohort or cut, from experiment.pre_*_2
  • Adjusted effect = observed minus old-user share × PAB: PAB covers only users who existed before the test, so a result with new users in it takes the old users' part of it (share of DAU-days of that result); old users take it in full, new users have none
  • My addition: PAB uncertainty is estimated from the 30 daily pre-test paired differences and combined with the observed uncertainty (square root of the sum of squared half-widths). Point estimates are unchanged
  • Assumption: new users carry no pre-existing gap between the variants, so nothing is subtracted for them

Where PAB is not available (†)

  • New users and the D00 to D30 cohorts, because PAB covers users who existed before the test
  • These show observed values, marked †

Conf and the reading

  • Conf is the confidence that the PAB-adjusted effect is not zero: 1 minus the two-sided p-value of the adjusted effect against its combined standard error (t distribution, days minus one degrees of freedom). It is not the probability the effect is large
  • The meaningful line is 1% (10 bps for retention)
  • Whole 95% interval beyond the line: upside or downside
  • General metrics, whole interval within plus or minus 1%: neutral
  • In between, Conf above 85% counts as sufficient evidence and the size decides: at least 1% (10 bps) is upside or downside, smaller is neutral
  • Conf of 85% or less: neutral (insufficient evidence; hover a label for which)

Metric definitions

  • Revenue is from experiment.revenue_without_xpromo (ad network "overall"); xpromo is excluded on both sides
  • Session time is session_length divided by DAU, in minutes; sessions per DAU from experiment.sessions
  • Rolling D1/D3 is users active on or after day 1/3 following the activity date, divided by users, from experiment.rolling_retention
  • Engagement actions are per DAU from experiment.engagement, puzzle_type "overall"; the puzzle split uses the same table
  • Classic DX is users active on day X after install divided by installs (experiment.retention over experiment.installs); LTV DX is ad plus IAP revenue in the first X days per install (experiment.revenue_cohort); LTDays DX is active days in the first X days per install (experiment.active_days)
  • Rolling LTV D7 is revenue earned over the following 7 days by the users active on a day, divided by that day's DAU (experiment.rolling_ltv, rev_type "Independent" for the total)
  • Economy is in-game cash from experiment.economy, cash_type "cash", category "overall": earned, spent (stored negative, shown positive), purchased, and net = earned minus spent; earners and spenders are users with any earn or spend that day

Limits and not run

  • Many drill-down cells are tested with no multiple-testing correction, so a single upside or downside cell is a lead, not a finding
  • Small cells (IAP, ad-on-inactivity, old cohorts) are spiky
  • Not shown unless asked: country and install-source deep dives
  • Version 3 does not exist for this experiment on Android; version 4 was read on request. Rolling LTV and the install-cohort metrics have no PAB, so they are observed only
  • Not run: session-length percentiles; device cuts; crashes
